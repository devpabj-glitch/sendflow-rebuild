## Ressalvas (menores, não bloqueantes)

1. **Condicionais "se ratificado" residuais (D-PEND-2 × D16):** o contrato carrega a condicional em ~6 pontos (§3.2 linha DELETE, T6/T7/T13 "se ratificado", §9.7, §10). A D16 **ratificou** — a implementação deve ler todas essas linhas como ATIVAS. Recomenda-se uma nota de ativação no cabeçalho (ou pass editorial) para o implementador não "pular" o DELETE por ler a condicional. Não muda a semântica contratada.
2. **Exemplo `limitPessoas: 350` (§3.1):** 350 é valor **visto** na referência (CRG-06) e o PM L34 diz que valores vistos são exemplos, nunca defaults. O default real do contrato é `null` (sem teto) — correto — mas o exemplo pode induzir a A2 a tratar 350 como default. Trocar por valor neutro ou anotar "valor ilustrativo, default = null".
3. **"Referência como filtro → 200 vazio" é padrão novo no produto:** F2/F3 não têm filtro por id referenciado, logo não há precedente direto. A escolha é correta (não vaza existência; coerente com filtro sem correspondência), mas deve ser comunicada à A2: lista vazia com `releaseId` válido ≠ id errado (malformado → 400 cobre o typo). Registrar para uniformidade futura quando outros filtros por referência surgirem.
4. **`seq` decai posteriores quando DELETE é executado (§9.7):** com a D16 ratificada, este efeito agora é real (não hipotético) e está declarado. Consequência inevitável da derivação sem coluna; impacto só visual. A A2 não deve tratar o número sequencial da linha como identidade estável entre exclusões.
5. **"70/70" é baseline da F4, não teto:** T10 declara a suíte vigente "70/70, 7 arquivos, na data da F4" — com `groups.test.ts` a contagem crescerá. O gate REG-01 é a suíte integral verde **sem regressão** + gates `typecheck`/`test`/`build`/`audit`, não o número 70 fixo. Redação já condizente; registrar para evitar leitura literal futura.

## Recomendações

1. **Ativar D16 editorialmente** antes da implementação: nota no cabeçalho do contrato ("D-PEND-2 ratificado pela D16 — ler toda condicional 'se ratificado' como ATIVA") ou edição pontual das ~6 ocorrências.
2. **Neutralizar o 350 do exemplo §3.1** (ressalva 2).
3. **Acrescentar ENT-04 [PROP] à tabela §10:** a pertença exclusiva a uma campanha foi implementada como FK obrigatória (leitura mínima estrutural — sem pai, GRU-02/03 não existem; correta), mas o "[PROP] link próprio 1:1" do ENT-04 segue pendente de DEC-11 e não aparece na tabela de pendências. Incluir para rastreabilidade.
4. **Orientações à A2:** "Redirect x/limite" é exibição pendente de DEC-05 (sem semântica de servidor; contadores serão 0 honestos nesta fatia); lista vazia com `releaseId` é resultado honesto; número sequencial não é identidade estável (DELETE decai ordinais posteriores); sem coluna Suspenso/link/tipo — não exibir o que o servidor não tem (DIR-04).
5. **Ao implementar:** manter o gatilho de borda FORA (sem consumidor AUT/FIL) e a demanda preservada como pendência; quando a fatia do gatilho chegar, exigir registro de transições/eventos dedicado — nunca reutilizar `updated_at` (já correto no risco §9.6).
