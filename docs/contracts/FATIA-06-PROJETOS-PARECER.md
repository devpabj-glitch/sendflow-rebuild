## Parecer específico sobre o D-PEND-3 (ponto obrigatório deste A4)

**Favorável à extensão do vocabulário de erro.** O 409 é o código HTTP correto para recusa dependente de estado com recurso íntegro (semântica de conflito, não de erro de validação do input); o produto já tem 409 (`AUTH_EMAIL_TAKEN`, F1), logo não cria categoria nova de transporte; o nome `PROJECT_NOT_EMPTY` é autoexplicativo sem revelar contagem; corpo genérico **fixo, sem `details`**, idêntico para qualquer projeto não-vazio (T4d) — o design fecha todas as vias de vazamento de cardinalidade. A leitura cruzada com o `releaseCount` público no GET da própria org confirma que o 409 não expõe nada que o recurso já não exponha ao mesmo público. Ratificação pela D21 é coerente; nenhuma objeção.

## Ressalvas (menores, não bloqueantes)

1. **Ativação editorial D19/D20/D21 pendente:** o contrato carrega "implementação BLOQUEADA até parecer A4 + D-PENDs 1–3" e condicionais "se ratificado" em ~7 pontos (§0 cabeçalho, §0.1, §2 comentário do SQL, §3.2 linha DELETE, §9.1, §10). Com este parecer e as decisões D19/D20/D21 tomadas, falta a **nota de ativação** no cabeçalho (precedente F5 §0 "Nota de ativação") para o implementador não "pular" o DELETE/409/drop por ler a condicional. Pass editorial do A1; não muda a semântica contratada.
2. **`accountCount` é derivação indireta (decisão técnica §0.3/§4.2):** conta DISTINCT de contas via `release_accounts` das releases do projeto — leitura correta de ENT-13/FLX-10 (o projeto não tem link direto com conta no PM), mas é a **interpretação** que define o número da coluna "Contas". Se DEC-16 ou uma futura vinculação direta projeto↔conta mudar o significado de "contas do projeto", o count muda de valor (não de shape). Declarado no §4.2 e §9.6; recomenda-se visibilidade explícita ao dono junto da DEC-16.
3. **pg-mem × FK RESTRICT (§9.2):** a aplicação da restrição no pg-mem pode diferir do PostgreSQL real; o gate primário é o COUNT na transação da API (correto), a FK é defesa-de-profundidade para o banco real. T9/T13 devem registrar o comportamento **efetivamente obtido**; a via FK fica evidência-L até o smoke em banco real (E2E-01). Aceitável e declarado.
4. **Down reversível no schema, não nos dados + acoplamento código×schema novo (§8):** qualquer vínculo gravado é perdido no down (coluna text renasce vazia) e reverter o código de releases sem rodar o down quebra INSERT/PATCH (text → coluna uuid). Regra operacional declarada ("reverter código exige reverter migração"); o dono deve ratificar conforto com essa restrição permanente de rollback — é o custo real da D20.
5. **"86" é baseline da F5, não teto:** com `projects.test.ts` a contagem cresce; o gate REG-01 é a suíte integral verde sem regressão + gates `typecheck`/`test`/`build`/`audit`, não o número literal. Mesma ressalva 5 do parecer F5; registrar para evitar leitura literal futura.
